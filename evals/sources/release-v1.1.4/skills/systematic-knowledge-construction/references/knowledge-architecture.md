# 知识架构：必要完整性、因果路径与迁移

> 主 Skill 的知识建模细则。适用于**任何知识性问题**；局部问题也应具备局部完整性。以下均为思考工具，不是输出模板。

## 1. 范围由理解任务决定

从当前问题定义 `scope fence`：中心对象/真实目标、必要先修、关键原理、上下游接口、边界条件、已知背景与用户已掌握部分；识别暂不涉及的邻域。系统性不是领域覆盖率最大化，而是**本问题所需概念和关系不缺失**。

选择相应知识结构：
- **局部概念**：对象/定义 → 存在理由 → 运行机制 → 关键依赖/区别 → 必要例子与边界。若一种概念存在多种语义，说明当次语境。不能因为提问短而省略中间机制。
- **完整领域**：中心问题与适用边界 → 主要分支/阶段 → 核心对象与前提 → 分支之间的依赖/交互 → 各分支原理、推导与应用 → 错误条件及验证；先广度识别主干，后分配深度。
- **多模块系统**：整体目标与约束 → 模块责任/接口 → 业务、数据、控制和状态关系 → 故障和横向约束 → 端到端效果验证。
- **非工程学科**：按该领域的知识逻辑（概念/公理、因果理论、证据、推理、反例、应用）调整，不套软件流程。

相邻领域只引入有实质解释力的知识。边界不是断绝关系：必要接口必须解释“为何相关、影响哪一个结论”。

## 2. L0–L5：可选内部核验镜头

| 镜头 | 检查的问题 | 何时有价值 |
|---|---|---|
| L0 目标与边界 | 研究什么、解决什么、在哪些条件下成立 | 判断范围与前提 |
| L1 主要构成 | 必不可少的部分及其分工是什么 | 复杂对象和全域主干 |
| L2 关系与依赖 | 上下游/横向怎样连接、约束怎样传播 | 拒绝知识名词堆砌 |
| L3 机制与实践 | 为什么有效、怎样从输入走向输出 | 需要真正理解或实现 |
| L4 边界与故障 | 哪个条件下失效、如何识别或处理 | 防止误用或生产事故 |
| L5 证据与验证 | 如何证明正确、怎样衡量与演进 | 决策、实验和交付 |

这些镜头**不代表必须逐层写出**、不代表所有节点需同样深挖、更不限定问答长度。单点问题也要以相关镜头完成必要理解。若用户不需要生产指标，不添加 L5 企业指标。

## 3. 用因果边替代罗列

每个核心节点内部可思考：`对象 / 作用 / 输入 / 输出 / 前提 / 过程 / 依赖 / 失败 / 验证 / 证据`。关键关系至少交代两端、方向、作用机制、成立条件及其后果：

- **先修/原理依赖**：理解 A 是解释 B 的前提；关键术语先建立必要含义。
- **数据与控制**：A 产生的数据经什么转换交给 B，谁在何条件触发下一步。
- **状态/反馈**：状态由谁写、谁读，转换何时发生；反馈改变后续决策的机制。
- **约束传播**：输入质量、资源、权限或分布变化如何改变效果/成本/安全。
- **横向耦合**：缓存与授权、重试与幂等、模型上下文与检索精度等。给出关系的原因，不只画一根箭头。

解释核心链路时优先回答：为什么需要这一步、它消除了哪一种不确定性、上下步如何交接、少了它会怎样。不能从“LLM 给出参数”直接跳到“工具成功”而漏掉解析、校验、权限和业务错误。必要时给含具体输入、状态和输出的最小逐步实例或反例。

## 4. 双向覆盖与深化

- **自顶向下**：中心目标 → 必要分支 → 分支接口 → 决定性机制 → 实例与限制。对于完整领域先建主干（breadth first）避免局部沉没；对于局部问题不展示全球地图。
- **自底向上**：从真实问题、典型输入、边界用例和失败路径反推缺失的必要知识。能否实际使用或向别人准确解释，是检查结构充分性的信号。
- **相互校准**：找到缺失节点时只补充使当次回答闭合的知识；若某分支删除后不影响理解、应用、判断或验证，则删减。

不同层级之间有循环或反馈时要解释它属于正常迭代还是不良依赖。不把一种算法实现的特性提升成通用定理，不把特定库的默认值当普遍定义。

## 5. 具体局部例与全景例

**Pydantic BaseModel（局部）**：说明字段声明与数据模型、初始化/验证时的类型转换和约束、`ValidationError`、`model_dump()` 序列化，区分结构/类型验证与业务事实、权限检查。用一个字段不合法的小例子说明失败发生在哪层。若用户转向 Agent tool calling，则拓展到整个工具调用验证链，不自动把每次 BaseModel 概念题写成企业项目。

**HNSW `efSearch`（局部）**：它控制查询时底层候选集搜索宽度（具体 API 参数语义随实现而定），影响探索程度、召回和延迟；说明与 `M`（图连接程度）、`efConstruction`（构建搜索宽度）的关系。更大通常提高召回机会但增加工作量，实际效果需在固定索引/数据分布和精确近邻 ground truth 下测 Recall@k 与 P95。无需展开 HNSW 每一个构图环节。

**HNSW 全景（全面任务）**：近似最近邻与距离定义；多层概率抽样图结构；插入导航、邻居选择与剪枝；查询上层贪心导航与底层扩展；候选队列/visited；`M / efConstruction / efSearch` 和成本耦合；更新删除；维度与距离、偏斜分布和碎片化故障；基于精确 ground truth 的 Recall@k、P50/P95、内存/建图代价。层上节点仍是数据向量的子集，不是聚类中心。

**Transformer 全景**：输入 token/嵌入/位置信息 → Self-Attention（Q/K/V、缩放点积、mask、softmax） → 多头组合 → 残差和归一化 → 前馈层 → 堆叠 → 训练目标及推理时的不同信息流；区分原始 Encoder–Decoder、Encoder-only 和 Decoder-only。推导应讲清 QKᵀ 的意义、缩放及 mask 的作用、复杂度与长上下文权衡，而不是只报公式。必要时结合张量维度/小型算例、KV Cache、预训练和部署边界，但不把每个相关方向都当主干。

## 6. 连续追问与知识迁移

沿对话当前可见的已建立概念、符号、假设、系统版本继续，不机械从初级定义重讲。追问“为什么、具体怎么实现、出错怎么办”时扩展受影响依赖闭包：补充一段机制、一个反例或一个实践证据，使前后解释衔接。用户改变约束时重检受影响的选择和上下游推导，说明哪些结论仍有效。发现旧回答的错误需明确修正并交代波及范围。

Skill 不存储真正的知识图数据库或保证跨会话永久记忆；只有宿主实际可提供的上下文、附件或记忆可被承接，缺失时不得假装已知。

## 7. 完成检查

问自己：回答是否真正解决提问？读者能否解释关键因果而非背术语？是否有必需的先修未定义、机制跳步、遗漏的关系、未说明的边界？是否存在和目标无关的知识扩张？必要的推导、验证或实践是否能复现？若不满足只修补对应节点与依赖，不以展示知识地图替代内容。
